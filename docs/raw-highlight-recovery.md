# RAW 显影中的高光重建

## 责任与顺序

高光重建是 native RAW 显影内部步骤，不是独立图节点。顺序为：解码/线性化 → 相机域重建 → [独立镜头校正](lens-correction.md) → 含所选白平衡的颜色矩阵 → 配方 HueSatMap → 固定场景标定 → EV → signed FP32 AP1。输出色域、CAT、Log 曲线及编码器不实现或配置第二份高光算法。

原始相机观测保存在独立缓冲。交付用重建缓冲仅存在于受影响帧；没有受影响值时不分配。测光调用禁用重建，继续使用原始观测、原始相机饱和掩码及既有颜色配方。因此切换交付恢复策略不改变去闪解算。用户 EV 作用在重建以后，不能改变 RAW 饱和判断。

## 证据边界

当前支持已测量的 SDK 整数 Linearize → FP32 camera 域：其归一化上限为每通道1。证据来自解码域，并不冒充原始 CFA 饱和掩码。存在 OpcodeList2/3 或 float-source 时，当前端点语义不受支持，保留原数据并报告 unsupported；不能从直方图猜一个白点。

每通道过渡宽度为 max(0.005, 8 / storage_range)，storage_range 由当前 LinearRaw 黑白端点提供。这是解码域近端点可靠度带，不是固定曝光或 AP1 高光阈值。SDK 实际 CameraWhite 提供与颜色矩阵一致的中性向量 n，最大分量归一化为1；不另施加 WB。

## 算法

### 观测可靠度

对通道观测 y、上限 s 和过渡宽度 d，令：


t = clamp((s-y)/d, 0, 1)
r = t²(3-2t)


r=1 的通道保持位级不变，包括负值。仅当至少一个通道 r<1 时才进行补全。数据高于1并不自动表示 RAW 饱和：必须有解码器支持的端点证据。

### 原始可靠邻域的颜色先验

只使用三个通道均为正、均未进入可靠度过渡带的原始像素作为颜色种子。每个种子计算白平衡归一化的对数色度：


z_c = log(y_c/n_c) - mean_k(log(y_k/n_k))


接近可靠截止点时，种子权重在4d范围内 smoothstep 退至0；接近信号下限时也退至0，避免一个微小噪声令整格颜色先验突然消失。信号下限为每通道上限的1e-5，此限制只用于颜色种子/比值计算，不裁剪输出观测。

16×16像素格只存权重、色度一阶/二阶矩，建立逐层2倍聚合金字塔，最大格步长不超过长边约1/16。不会把聚合格输出成低分辨率恢复图。

每个受影响像素在各层查询周围3×3格，权重由以下因素相乘：

- 原始可靠种子占比；
- 空间紧支撑 C1 核，每轴为 max(0,1-(distance/1.5)²)²；格退出查询时权重已经为0；
- 16/当前格步长，使远尺度影响减弱；
- exp(-8·可靠通道对数色比误差 - 4·格内色度方差)，抑制不同颜色边界和相互冲突的邻域。

只有可靠通道对参与色比约束；只有一个通道可靠时不能虚构另一条边缘证据。原始种子固定不变，重建值绝不重新成为种子。

设有效权重和为 mass，对加权色度均值 mu 使用：


u = clamp(mass/0.5, 0, 1)
confidence = u²(3-2u)
q_c = exp(confidence · mu_c)


缺少支持时 q 平滑趋向中性 [1,1,1]。上述常量属于算法 revision 1 的可测试实现参数，不是已标定的相机物理噪声模型。

### 可靠观测约束下的尺度估计

相机域模型为 x_c=L·n_c·q_c。只用原始观测，以可靠度加权最小二乘估计亮度尺度：


L_fit = sum_c(r_c·q_c·y_c/n_c) / sum_c(r_c·q_c²)
L_min = max_c((1-r_c)·max(y_c,0)/(n_c·q_c))


L_min 随可靠度连续增长，避免在最后一个通道触顶时突然引入新的尺度约束。取 L_anchor=max(L_fit,L_min)。可靠观测权重耗尽时，用 min(1,sum(r·q²)/0.05) 在 L_anchor 与 L_min 间过渡；全饱和时选择 L_min。该最小延续不是对真实光源亮度的测量。

最后只补全不可靠通道：


estimate_c = max(y_c, L·n_c·q_c)
x_c = r_c·y_c + (1-r_c)·estimate_c


r=1 的分量直接保留原 float，不经过上述重新舍入。恢复值允许超过1，没有 AP1/Log/sRGB上限裁剪。

### 三类情况

- 未饱和：所有观测约束成立，原样通过。
- 部分饱和：可靠通道锚定尺度，局部颜色先验约束缺失通道；无颜色证据时采取保守中性先验，绝不改写可靠观测。
- 全饱和：利用有限距离内可信颜色；支持消失时退向中性，选择保守最低尺度，不生成纹理或凭空增加若干EV。

## 接口和运行记录

native stdout consumer 支持 --highlight-recovery on|off，独立调用默认 off 以便保留纯矩阵显影和诊断对照。Rust 产品 develop 明确传 on，analysis 明确传 off；analysis 即使收到 on 也不会消费重建结果。产品没有额外图节点或依输出 profile 切换的高光实现。

metadata 的 highlight_recovery 单独记录 revision、请求/有效状态、证据来源、受影响/部分/全部饱和及空间/保守补全像素数和最大通道倍率。颜色矩阵合同 algorithm_revision=4 不冒充高光版本；高光 revision 独立为1。Rust 要求交付返回匹配的高光合同，并在同名运行日志中逐帧记录 kind=highlight。unsupported 是能力限制，不是成功恢复。

## 限制

- 不是 DaVinci 私有算法复刻；其基础显影可能已经执行白点/高光处理。
- 单帧空间算法，无跨帧运动估计或时域状态。数值连续性测试不等于真实运动序列已完成视觉验收。
- 颜色种子要求三通道可靠；大面积彩色饱和、只有一个可靠通道或远处颜色边界仍可能保留偏色或损失颜色。本实现不能保证所有彩色光源都被准确恢复。
- 全通道饱和的真实辐射、纹理和光谱不可从单帧恢复。保守中和不能称为找回真实颜色。
- 格内色度方差及可靠色比只提供边界抑制，不是语义分割。
- 受影响帧额外需要一份相机 FP32 缓冲（8K约398MB）和小型格金字塔；并发仍由现有显影调度约束，没有宣称零额外内存。

## 验证

独立于 SDK 的单元检查覆盖 signed/无饱和恒等、未知 HDR 端点透传、原观测不变、单/双通道合成真值、邻域彩色恢复、全饱和中性延续、确定性、端点与种子退场连续性、取消和非法数值。真实 SDK 集成检查矩阵/HueSatMap顺序、EV等变性、source/prepared一致、测光隔离以及未知opcode端点明确透传。

真实 DNG 和指定达芬奇 TIFF 的本次比较以高光品红为目标，不以全图相似度为验收条件。量化品红指标为 min(R_signal,B_signal)-G_signal；它仅用于选定中性高光ROI诊断，不是产品判色阈值，也不应用于判断合法紫色是否错误。
