# Raw Timelapse 桌面界面初版

采用 Qt 6 Quick / QML 设计 macOS 和 Windows 共用的界面。QML 负责窗口和交互，Rust/C++ 管线负责读取序列、显影和导出。初版交付单帧适配预览，色彩管理、分块渲染和高分辨率缩放留待后续版本。

## 工作区

- 应用启动时显示空工作区，画面中提供「选择文件夹」。工具栏可打开、替换或关闭 RAW 序列目录，并显示当前输入目录的完整路径。空间不足时用中间省略号保留路径首尾，悬停时可查看完整路径。
- 沿用 CLI 的目录校验和自然数字排序。目录验证成功后，释放旧序列的帧、预览缓存和预处理上下文，清空画面并定位新序列第 1 帧。关闭素材也执行同样的释放。目录选择取消或校验失败时保留当前序列。
- 左上按宽高比完整显示最近一次渲染成功的帧。拖动时间线或改变白平衡、镜头校正、色彩时异步请求预览，并在画面内显示「渲染中」。新请求等待时保留上一帧，新结果就绪时替换画面并收起标签。失败时保留上一帧并显示错误。更换序列后，上一序列的画面和结果立即失效。
- 左下固定显示整个序列，左端是第 1 帧，右端是第 N 帧。播放头的位置按 `(帧号 - 1) / (N - 1)` 计算，只有 1 帧时固定在起点。点击和拖动实时选帧，支持键盘逐帧定位。时间线没有缩放、平移、缩略图或悬停预览。帧率只影响导出。
- 右侧依次显示「预处理」和「导出」。界面直接显示可调字段，处理图由内部管线管理。

## 预处理

「白平衡」有「使用首帧」和「使用各帧拍摄值」两项，对应处理 profile 的 `white_balance: "first-frame"` 和 `"per-frame"`，默认使用首帧。前者使用同序列首帧的 RAW 拍摄白平衡，后者使用当前帧各自的 RAW 拍摄白平衡。

镜头型号和匹配结果随当前帧刷新。镜头匹配复用现有 Prepare 的内嵌校正/LCP 判定，型号文本来自原始文件元数据。匹配结果应与用户选择的校正开关分开获取，因此取消勾选后仍能显示型号及支持状态。

| 当前帧状态 | 文本 | 复选框 |
| --- | --- | --- |
| 型号已知，匹配到可用校正 | `{镜头型号}` | 可用，跟随处理 profile 的镜头校正设置 |
| 型号已知，未匹配到可用校正 | `{镜头型号}（不支持校正）` | 可用，仍可设置整个序列的策略，当前帧跳过无可用模型的分量 |
| 无镜头型号 | 无镜头信息 | 禁用且显示未勾选，切回可用帧时恢复序列设置 |

用户勾选和取消勾选分别写入 `lens_correction: "auto"` 和 `lens_correction: "off"`。切到无镜头信息的帧时，只更新该帧的显示状态，保留序列级设置。元数据读取失败单独报告。

## 导出

- 「色彩」从管线的色彩列表生成，包含 sRGB、自动选择Log、Canon Log 2/3、DJI D-Log/D-Log 2、Nikon N-Log 和 Sony S-Log3 的两种色域，写入 `output_color`。
- 「自动选择Log」继续使用 `auto-log`，调用管线现有的首帧相机识别和 Log 选择。选项显示解析结果，例如「自动选择Log（Canon Log 2）」。切换目录时重新解析，拖动到其他帧时沿用该序列的结果。解析失败时显示原因，改选明确的色彩选项后可继续导出。
- 预览应用所选色域和曲线，直接显示预览像素。初版不做显示器色彩管理或 Log 到显示空间的映射。
- 「输出帧率」允许键入正数，默认 60 fps，最大 1000 fps。整数写入 `fps`，小数转换成精确有理数字符串。载入已有有理数值时保留原值，直到用户编辑。
- 右下角的「导出」在队列空闲时立即启动任务。已有任务运行时，按钮显示「加入导出队列」，按加入顺序执行，同时只运行一项。
- 点击按钮时保存输入目录、输出路径和当时的完整处理 profile。切换输出色彩时沿用目标 Log 的默认参考增益和 CAT，内置 sRGB 的 `log_reference_gain: 1` 不作为其他色彩选项的覆盖值。输入目录和输出路径沿用 CLI 的约定。队列保留这些运行参数，关闭或更换素材时仍可继续导出。

## 导出队列

- 点击窗口右上角的队列按钮，在按钮下方打开弹窗。再次点击按钮、点击弹窗外或按 Esc 关闭。查看队列期间预览和导出继续运行。
- 任务主标题显示输入目录路径，空间不足时使用与工具栏相同的中间省略规则。每项只显示路径和状态，遇到失败时显示错误，随后继续下一项。处理 profile 保存在任务中供导出使用。
- 「清除所有」移除已完成和失败的记录。运行中与等待中的任务继续执行，磁盘上的导出文件保留。
- 完成后显示文件夹图标，打开实际导出文件的父目录。用 `QUrl::fromLocalFile` 构造目录 URL，由 `QDesktopServices::openUrl` 交给 macOS Finder 或 Windows 文件资源管理器。目录不可用或系统拒绝打开时反馈错误。[Qt 桌面服务](https://doc.qt.io/qt-6/qdesktopservices.html#openUrl)

## 实现边界

预览使用独立的 Rust 进程复用 Prepare / Develop 和输出色彩转换。预览端保留一个进行中的请求和一个可替换的最新请求，拖动或修改选项时合并中间请求。只有当前序列的最新请求可以更新画面和渲染标签。显影在原尺寸完成高光恢复，再在至多 1440 像素长边的相机线性画面上做镜头校正和 HueSatMap。切换输出色彩复用已经显影的预览帧。依赖整段序列的去闪和自动参考增益扫描留在完整导出，单帧预览对自动增益使用配置的目标值。

导出队列由应用管理，独立于工作区的预览会话。每个运行中的导出使用独立进程和工作目录，同一时刻只启动一个导出进程。导出可以占用计算资源，界面仍能打开、关闭和预览其他素材。预览会话或它的临时文件释放时，不影响运行中和等待中的导出。

完整导出沿用现有管线。桌面层使用 Qt 的路径、进程和文件夹接口。当前 Adobe DNG SDK 显影适配器的构建仍限定 macOS，Windows 上的完整 RAW 预览和导出需要可用的 Windows 版适配器。构建方式和外部工具位置见 [桌面端 README](../desktop/README.md)。
